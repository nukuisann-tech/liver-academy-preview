原本 08 §16　MONETIZATION RHYTHM 柱　原本内のタグ: [EXPERT ADDITION]

原本内のタグ[EXPERT ADDITION]

常時課金圧をかけない。

GOAL → PARTICIPATION → CONTRIBUTION OPPORTUNITY → RECOGNITION → PROGRESS → CELEBRATION → RECOVERY

ギフトが自然に発生する山を作る。

原本 08 §17　Monetization Periodization 原本内のタグ: [CASE / INFERENCE]

原本内のタグ[CASE / INFERENCE]

BUILD → ACTIVATE → UNITE → PEAK → RECOVER → CONSOLIDATE

BUILD

新規・関係性

ACTIVATE

低負荷参加

UNITE

共通目標

PEAK

イベント・バトル

RECOVER

課金圧を下げる

CONSOLIDATE

新規を常連へ

売上最大化 ≠ 毎日の売上最大化

原本 08 §18　Fan Fatigue 原本内のタグ: [EXPERT ADDITION]

原本内のタグ[EXPERT ADDITION]

支援負荷が高すぎると離脱する。

見る：

  • ギフター人数減
  • 同じ人だけ投げる
  • イベント反応低下
  • 課金CTA時に沈黙

対応：

  • Free participation
  • 通常配信
  • 感謝
  • Recovery week
原本 08 §20　Failure Modes 原本内のタグ: なし
「ギフトください」を繰り返す

関係上流を飛ばしている。

高額者だけ会話

PAYWALLED BELONGING化。

大きく叫べば正解

Brand Fit不一致。

イベント連打

Support Load増大。

金額を人格評価にする

コミュニティ崩壊リスク。

原本 14 §7　REVENUE WAVE DESIGN 原本内のタグ: [CASE / EXPERT ADDITION]

原本内のタグ[CASE / EXPERT ADDITION]

売上は毎日同じ最大値を狙わなくてよい。

BUILD → BUILD → ACTIVATE → PEAK → RECOVERY → BUILD

Phase KPI

BUILD：New / Return / Comments
ACTIVATE：Participants / First gifters
PEAK：Revenue / Gifters
RECOVERY：Return / non-paid engagement

SAME KPI EVERY DAY = WRONG
