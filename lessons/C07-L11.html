節の全文を読む原本 01 §5　各ファネルの意味
5.1 DISCOVERY｜見つけてもらう

主な入口：

  • TikTok LIVEおすすめ
  • ショート動画
  • フォロー中ユーザー
  • コラボ / バトル
  • ランキング / イベント
  • 切り抜き
  • 外部SNS

ここでは「露出量」が重要。

ただし露出があっても、次のENTRYが弱ければ成果にならない。

5.2 ENTRY｜入室してもらう

視聴者は、LIVEを表示されたあと「入る / 入らない」を判断する。

影響要素の例：

  • 顔・表情
  • 背景
  • 画面の明るさ
  • タイトル / テーマ
  • 本人のキャラクター
  • 動き
  • 何をしている配信か理解できるか

Projectでは、入口の考え方を次の式で整理する。

EXPOSURE × ENTRY RATE = ENTRANTS

これはTikTok公式指標の式ではなく、成長診断用の概念モデルである。 [E]

「人が来ない」を、露出不足と入口不足に分けて考えられる。

5.3 FIRST IMPRESSION｜入った瞬間に意味を伝える

入室者は短時間で、

  • 誰なのか
  • 何をしているのか
  • 自分がいてよい場所か
  • 面白そうか
  • コメントできそうか

を判断する。

このため、初見対応では次を早く伝える。

IDENTITY → ACTIVITY → VALUE → PARTICIPATION CUE

例：

「こんばんは、舞台俳優の○○です。今日は次の役作りについてみんなに相談してます。初見さんも“どっち派？”ってコメントしてね。」

人物・テーマ・見る価値・参加方法が一度に伝わる。

5.4 RETENTION｜居続けてもらう

滞在は、「帰らせない」ことではない。

帰れない配信ではなく、帰りたくない配信を作る。

滞在に影響する代表要素：

  • 入室後すぐ内容が分かる
  • 会話が止まらない
  • コメントが拾われる
  • 自分も参加できる
  • この先に何か起こりそう
  • 感情の変化がある
  • 企画・目標・進捗がある
  • 内輪だけで会話していない

TikTok公式はLIVE推薦において視聴時間等のユーザー反応を利用すると説明している。 [A]

ただし「平均視聴時間が唯一の最重要指標」「○分ならおすすめに載る」といった固定ルールは扱わない。

5.5 ENGAGEMENT｜見る人から参加する人へ

参加のハードルには段階がある。

例：

  • タップ / いいね
  • 投票
  • コメント
  • フォロー
  • シェア
  • ファンクラブ等
  • ギフト

重要なのは、いきなり最も負荷の高い行動だけを要求しないこと。

Projectの基本モデル：

WATCH → TAP → COMMENT → FOLLOW → RETURN → SHARE → JOIN → SUPPORT → ADVOCATE

これを PARTICIPATION LADDER と呼ぶ。 [E]

5.6 RELATIONSHIP｜「誰か」から「知っている人」へ

関係構築では、視聴者が「自分を認識してもらえた」と感じる体験が重要になる。

代表的な行動：

  • 名前を呼ぶ
  • 前回の話を覚える
  • コメントへ質問で返す
  • 変化に気づく
  • 感謝を具体的に伝える

Projectでは、名前呼びの役割を2つに分ける。

  • 新規：ATTENTION CAPTURE
  • 再訪者：RELATIONSHIP CONFIRMATION

同じ行動でも、ファネル上の役割が違う。 [E]

5.7 FOLLOW｜つながりを残す

フォローは「ファン化完了」ではない。

フォローは、次に本人へ再接触する確率を上げる接点の1つ。

フォローを促す場合も、単なる「フォローして」ではなく、

  • 次回配信
  • 続きの企画
  • 定期テーマ
  • 本人の目標

など、フォローする理由を与える。

5.8 RETURN｜再訪

強いLIVEは、1回の視聴を最大化するだけではなく「また来る理由」を作る。

代表的な再訪要因：

  • 次回日時が分かる
  • 続きがある
  • 自分の名前・話を覚えてくれている
  • 常連儀式がある
  • 配信に居場所を感じる
  • 応援したいストーリーがある

終了時には、

感謝 → 次回予定 → 次回の見どころ

まで行う。

5.9 FANDOM｜この人を応援したい

ファンは、単に「よく見る人」ではない。

Projectでは、ファンダム形成を以下で捉える。

Recognition → Participation → Agency → Co-creation → Belonging → Return → Fandom

強いファンダムでは、視聴者が、

  • 自分も場に影響している
  • 仲間がいる
  • 本人の物語を一緒に追っている
  • 自分の応援に意味がある

と感じる。

5.10 MONETIZATION｜支援を売上へ変える

収益は、Relationshipの下流にある。

MONETIZATION IS DOWNSTREAM OF RELATIONSHIP DESIGN

Projectの重要原則である。 [E]

ギフトを「お願い」だけで生むのではなく、

  • 参加したい
  • 応援したい
  • 自分の貢献が見える
  • 目標が分かる
  • リアクションが楽しい
  • ストーリーを進めたい

という構造を作る。

5.11 ADVOCACY｜ファンが新しい人を連れてくる

最上流へ再び戻る段階。

  • シェア
  • 友人紹介
  • 切り抜き
  • SNSでの言及
  • コミュニティ内で新規歓迎

常連・古参: 場を開く言い方と、成長期の「遠くなった」への手当て　K-FAN-002　③ 専門家の整理・補強（実データ未検証）

補強の本文を読む状態: approved　確度ラベル: EXPERT・INFER
  • 型: ノウハウ・判断基準
  • Level: L1〜L3
  • status: approved（承認の対象は運用の指示。頻度・経過・効果を述べた文は [INFER] で未検証）
  • 判定: NEW
  • 確度: [EXPERT] [INFER]
  • 原本参照: [MK] 07 §2・§3・§5・§8・§9・§12／[MK] 05 §9・§10／[MK] 13 §1〜§3／[MK] 04 §11／[MK] 08 §19B
  • 元候補: review-fan MORE-FAN-03 ＋ review-talk MORE-TALK-05
  • キーワード: 常連／古参／内輪／新規が入りにくい／遠くなった／売れて変わった／人が増えた／昔話／名前呼びの偏り／役割
  • 内容:
    • (a) 常連が場を占めたとき
    • 原理 [EXPERT]: 切るのではなく「広げる・預ける・あとに回す」。常連の発言を止めるのではなく、新規が入れる入口に作り替える。常連は空気と売上の両方を支えているので、雑に切ると失うものが大きい。
    • 技法 [EXPERT]: ①橋渡し（常連の話題を、誰でも答えられる全体への問いに変える）②役割を渡す（場を一緒に作る側に置く）③予約して必ず戻る（「あとで」と言ったら戻る。戻らない予約は無視と同じ）④名前呼びの配分に自分で気づける状態にする ⑤場のルールはライバーが言う（古参が新規へ注意や指導を始めたら、責めずに引き取る）。
    • (b) 人が増えて認識が減ったとき
    • 原理 [EXPERT]: 少人数期の価値は、毎回名前を呼ばれ話が続くこと。人が増えると、同じ行動をしても返ってくる認識は減る。本人の貢献は変わらないのに返ってくるものが減るので、「自分は要らなくなった」「売れて変わった」と受け取られやすい。これは嫉妬ではなく喪失で、責めても説得しても解けない。（受け取られ方と「解けない」という見立ては、実ケースで確認していない推論 [INFER]。GAP-0010）
    • 手当て [EXPERT]: ①変化を先に言葉にする（不満が出てからの説明は言い訳に聞こえる）②認識の形を個別の会話から「役割と歴史」へ移す ③ゆっくり話せる回を定期的に置く。参加条件を支払額・在籍期間にしない（古参限定にすると新規との壁になる。所属の入口を課金にしない点は [MK] 07 §5。在籍期間についての記述は同節に無い）④節目で歴史を語るときは個人名の列挙ではなく「最初の頃のこの枠」という共有の物語として語る（名前が挙がらなかった人が傷つく）。
    • 見分け [EXPERT]: 昔話や内輪ネタの増加は、居場所を確かめる行動として出ることがある。見た目は内輪化（[MK] 07 §3）と同じだが対処は逆で、叱るのではなく役割を渡す。新規を締め出す言動が実際に出ている場合は K-FAN-003 のルール対応が先。
    • 判断基準 [EXPERT]: 成長局面では「新規の定着」と「初期メンバーの継続」を別の指標として同時に追う。全体の再訪が増えていても、初期メンバーの来訪が落ちていれば (b) が起きている。
    • 役割付与の線 [EXPERT]: 渡してよいのは歓迎・案内・企画の進行補助まで。注意・取り締まり・ルールの宣言は渡さない。依頼であって義務ではなく、断っても扱いが変わらない。
    • ガードレール: 役割付与を無償労働の調達や離脱防止の拘束として使わない。役割を持つ人を特権的に見せない。
  • 配信中・現場で人間がすること:
    • ライバーは、新規が入ってきたのに常連との会話が続いているとき、(a) の①〜③のどれかで開く。古参が新規に注意を始めたら、礼を言ってルールを自分の口で言い直す。
    • ライバーは、同接が増え始めた時期に、不満が出る前に (b) の①を言う。役割は選択肢として打診し、返事を急がせない。
    • コンサルは、録画の一定区間で名前呼びを書き出し、偏りを本人と確認する。初期メンバーの来訪を別枠で記録する。
    • 言い方の型（台本ではない）:
      • 開く: 「○○さんのその話、みんなにも聞きたい。みんなはどっち？」
      • 引き取る: 「教えてくれてありがとう。ルールは私から言うね」
      • 変化を先に言う: 「人が増えて、前みたいに全員とゆっくり話せなくなってきた。最初からいてくれた人のことは忘れていない」
  • 条件・例外:
    • 新規がほぼ入らない時間帯・少人数の枠では、常連と深く話すこと自体が価値。開くのは新規が入ってきたとき（[MK] 05 §9）。
    • 役割を望まず、静かに見ていたい初期メンバーもいる [INFER]。
    • 役割付与で初期メンバーの継続が保てるかは未確認（GAP-0010）。
  • 良い状態 / 悪い状態:
    • 良い: 新規の最初のコメントにライバーが先に反応している。予約した話に戻っている。初期メンバーが歓迎や案内を自分から行い、断った人も同じように扱われている。
    • 悪い: 名前呼びが 1 人に偏り続ける。初期メンバーのコメントが挨拶だけになる、来てもコメントしない。「人増えたね」「最近忙しそうだね」と距離を示す発言が出る。古参が新規を注意している。
  • 観測ポイント・KPI: 一定区間の名前呼びのうち最多の 1 人が占める割合（本人の過去比）／新規の最初のコメントに先に反応したのがライバーか常連か／予約した話に戻った件数／初期メンバーの来訪とコメントの長さの変化／新規の定着（別指標として並べる）。
  • NG（記録）: 人前でいじって黙らせる、急に無視する、常連同士を比べる／「古参なんだから分かってよ」と理解を求める／古参を特権階級として扱い新規の前で序列を見せる／離れた古参を配信で名指しして呼び戻す（罪悪感による拘束にあたる）／役割を断った人への反応を下げる。
