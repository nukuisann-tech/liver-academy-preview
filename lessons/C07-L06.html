2.5 売上を伸ばしてもファン信頼を壊さない

採用しない方針：

  • 過剰な課金煽り
  • 罪悪感を利用した支援要求
  • 愛情や親密さを課金額で販売する設計
  • 高額ギフターだけが人格的に優遇される序列
  • 新規が入りにくい閉鎖的な常連文化
  • 本人のブランドを壊す罰ゲーム・リアクション
  • 本業・契約・NDA・権利を毀損するコンテンツ

重要原則：

CONTRIBUTION RECOGNITION ≠ HUMAN VALUE HIERARCHY

貢献差は認識してよい。人間としての所属価値は課金額で序列化しない。

節の全文を読む原本 00 §2　Learning OSの基本原則
2.1 成長は「知る」だけでは起きない

学習サイクルは以下を基本とする。

LEARN → DO → MEASURE → REFLECT → MASTER

  • LEARN：原理・方法を理解する
  • DO：次回LIVEで実行する
  • MEASURE：数字・反応・観察で確認する
  • REFLECT：何が起きたかを振り返る
  • MASTER：再現可能な能力へ変える

教材を読了したことと、スキルを習得したことは別である。

2.2 数字は初期から見る。ただし高度分析は後から学ぶ

原則：

MEASURE EARLY, ANALYZE DEEPLY LATER

初心者も最初から最低限の数字を見る。

  • 配信時間
  • 視聴者数
  • 平均同接 / 最大同接
  • 平均視聴時間
  • コメント
  • いいね
  • フォロー増
  • ギフター
  • ギフト / Diamonds 等

一方、cohort、因果切り分け、Controlled Field Experiment、戦略転換などの高度分析は上位段階で扱う。

2.3 ブランドは後から付けるものではない

ブランドは配信開始前から存在する。

  • アイコン
  • プロフィール
  • 背景
  • 話し方
  • キャラクター
  • 配信テーマ
  • ギフトリアクション
  • SNS投稿
  • ファンとの距離感

すべてが「この人は何者か」を形成する。

したがってブランドは初期から学び、成長に応じて以下のように進化させる。

BRAND v1 → BRAND VALIDATION → BRAND SYSTEM

2.4 ファン化と収益化は別スキルだが、同じシステム

収益だけを切り離して考えない。

基本循環：

Recognition → Participation → Relationship → Belonging → Support → Recognition → Deeper Relationship

ギフトは人間関係の代替ではなく、関係・参加・意味づけの結果として発生する支援行動の1つとして扱う。

  • Level: L2〜L3
  • status: approved（承認の対象は運用の指示。頻度・経過・効果を述べた文は [INFER] で未検証）
  • 判定: NEW ＋ CONDITIONAL
  • 確度: [EXPERT] [INFER]
  • 原本参照: [MK] 07 §7・§8・§11・§12・§16／[MK] 08 §12・§19A／[MK] 09 §17／[MK] 22 §6・§8・§16・§23／[MK] 13 §11
  • 元候補: review-fan MORE-FAN-06 ＋ MORE-FAN-07（見える化と序列化の両立条件）＋ review-fan §4-7・§4-8
  • キーワード: ファン同士の嫉妬／誰々ばっかり／ひいき／当てつけ／古参と新規の摩擦／順位／貢献ボード／作戦会議／金額の割り当て／同調圧力
  • 内容:
    • 原理 [EXPERT]: ファン同士の嫉妬の燃料は、ライバーからの認識の「配分の見え方」。量そのものより、理由が見えない偏りが効く。認識の理由が金額に見えると、競争か諦めのどちらかが起きる。理由がその場への貢献に見えると、真似できる行動として広がる。（効果の向きは未観測の推論 [INFER]）
    • 可視化が生むもの [EXPERT]: 貢献が数字と順位で見えると、一部の人には動機になり、多くの人には「自分の額では意味がない」という諦めになる。上位の少数では、応援が順位を守る作業に変わりうる。
    • 認識の出し方 [EXPERT]: 人ではなく行動を褒める（何をしてくれたからかを言葉にする）。ファン同士の比較を自分の口から言わない。冗談でも言わない。
    • 敵意への対応 [EXPERT]: 気持ちは裁かない。敵意が行動として出た時点で、ルールとして全体に言う。繰り返す場合は個別に、モデレーター経由で対応する。古参と新規の摩擦ではどちらの味方もせず、今の枠のルールを言い直す（背景に古参の喪失感があれば K-FAN-002 を併用）。仲裁を配信の中でやらない（見世物になり陣営ができる）。当事者以外には「対応しています」とだけ伝える。
    • 見える化の両立条件 3 つ（[MK] 09 §17・22 §8 を使うときの条件） [EXPERT]: ①見せるのは参加の痕跡と全体の進捗。個人間の金額差・順位差をライバーの口から読み上げない ②無料の参加（コメント・シェア・新規の歓迎など）が有料の貢献と同じ場所に載る。有料だけが載る表は実質的に金額の順位表になる ③プラットフォーム側が順位を表示している場合も、ライバーがそれを話題の中心にしない（表示の現行仕様は未確認）。
    • 外部コミュニティの「イベント作戦」に付ける条件（[MK] 07 §7 を使うときの条件） [EXPERT]: 作戦共有の場は、熱心な人が善意で金額の割り当てを始めやすく、出せない人は黙って抜ける。ライバーが一切煽っていなくても支援の負荷が上がる経路になる。条件は次のとおり。
      • 「金額の割り当てをしない／個人への要請をしない／出していない人に言及しない」を明文化し、常に見える場所に置く。
      • 作戦の中身は「いつ・何で参加できるか」（時間、無料の参加方法、役割）を中心にし、金額を主題にしない。
      • ライバーまたは運営が定期的に場を見る。見られない規模なら作戦の場を持たない。
    • ガードレール: 認識の配分を意図的に偏らせて競わせない。ルールは支払額に関係なく同じに適用する（上位支援者にだけ甘い運用は他の全員に見えている）。モデレーターの人数・権限などの体制はこのユニットでは定めない（[MK] 21 の P1「10. Moderator / Community Governance」が既存の Gap）。
  • 配信中・現場で人間がすること:
    • ライバーは、特定の人に礼を言うとき、行動を添える。問題が起きていない平時に、枠のルールを全体へ言っておく。
    • ライバーは、嫌味・当てつけのコメントが出たら、誰のコメントかに触れずルールを言い直して話題を進める。揉め事の中身には配信中に入らない。
    • 運営・事務所は、外部の場を持つなら 3 条件を固定表示し、定期的に見る担当を決める。まとめ役が割り当てを始めていたら、善意を認めたうえで理由つきでやめてもらう。
    • コンサルは、貢献の表示物（ボード・読み上げの習慣）を両立条件 3 つで点検する。
    • 言い方の型（台本ではない）:
      • 行動を褒める: 「初めての人に説明してくれてありがとう」
      • ルールとして言う: 「ここでは、他の人への嫌味は無しでお願いします。誰が言っても同じです」
      • まとめ役へ: 「みんなを思ってくれているのは分かる。ただ、金額を割り振るのはここではやめたい。出せない人が居づらくなるから」
  • 条件・例外:
    • 少人数の枠では、全体へのルール宣言が特定個人への当てつけと分かってしまう。平時に言ってあることが前提になる [INFER]。
    • 競争を楽しみとして健全に遊べる層・枠はある。分かれ目は、降りる自由があるか／負けたときに誰も責められないか／少額・無料の人が蚊帳の外にならないか [INFER]。満たせないなら勝敗企画の頻度と強さを下げる（局面ごとの言い方は K-MON-002）。
    • つきまとい・晒し・脅しは関係調整の対象ではない。記録して事務所へ渡す（K-SAFE-002）。
  • 良い状態 / 悪い状態:
    • 良い: 礼に行動の理由が付いている。無料の参加が表示物に載っている。外部の場で金額の話が主題になっていない。ルールの適用が相手の支払額で変わっていない。
    • 悪い: 特定の 2 人が同時にいるとどちらかが黙る。「誰々ばっかり」という発言が出る。外部の場の発言者が数人に固定している。イベント後に静かに抜ける人が複数出る。少額層の参加が減る。
  • 観測ポイント・KPI: 嫌味・当てつけ・比較の発言の件数（本人の過去比）／外部の場での金額の話題の有無と発言者の偏り／イベント後に来なくなった人の人数／勝敗企画の前後での少額・無料参加者の再訪／礼に行動の理由が付いていた割合（録画で確認）。
  • NG（記録）: 嫉妬を熱量として使う（他の支援者との差を告げて競わせる。[MK] 22 §23 の嫉妬煽りにあたり、支援者の消耗と離脱を招く）／支援者同士の順位争いを実況する／揉めた片方を配信で晒す／ファンに自治を任せ、ファンがファンを取り締まる状態を作る（序列の固定と私的制裁につながる）／上位支援者にだけルールを緩める／外部の場での割り当てを「自発的な応援」として放置する。
  • 未検証・関連 Gap: 専用の Gap 番号なし。モデレーター体制の事例化は [MK] 21 の P1「10. Moderator / Community Governance」。条件を付けた効果は未観測（[EXPERT] のまま運用）
